### Open items found during hardening

- The release validator's discovery expectations (bare-origin issuer and `authorization_servers`, `twin:read` in `scopes_supported`) were found during hardening and are now met in code; `test_discovery_matches_the_release_validator_contract` mirrors them offline. The live check still runs only against the real deployment.
- Errors raised during consent (revoked membership, expired transaction, bad CSRF) return an HTML 400 rather than an error redirect, so ChatGPT receives no OAuth error response for them.
- Partial answers carry no marker, and the audit log does not record that evidence was partial. Likewise, when one service's grant is rejected and another service verified evidence, the answer cites that evidence with no reconnect prompt.
- Slack grants stored before H1 carry the old 24-hour expiry and need one reconnect after it passes.
- Only the `PUBLIC_BASE_URL` host is accepted on `/mcp`; a second public hostname gets 421, and the proxy must preserve Host.
- While refreshes of an allowlisted client metadata document fail, its last good client, including its redirect URIs, keeps serving for up to 24 hours (SEC-1).
- A stalled name resolver can leave one daemon resolver thread running until the operating system gives up; single-flight and the 60-second backoff limit this to about one per document URL per minute (SEC-2).
